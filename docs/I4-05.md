## Passes (dans l'ordre)

1. **product-owner.** Critères : (1) deux commandes Rust seulement, produit par code et recherche texte ; (2) ne part sur le réseau que le code ou le texte, plus un User-Agent générique ; (3) recherche en ligne sur geste explicite, 10 par minute au plus (garde Rust) ; (4) conversion pure, inconnu = `null`, fiche sans énergie ni macros refusée, code-barres à clé vérifiée ; (5) cache 90 jours dans `food` ; (6) scan iPhone, champ « Code-barres » PC et iPhone ; (7) cas dégradés en français ; (8) mention « Open Food Facts » et ODbL ; (9) écran de scan et client front hors du départ ; (10) H-12 et le scan restent UNVERIFIED, check-list de constat dans la matrice. Hors périmètre : recettes, favoris, photo IA, I5.
2. **architect.** Seule nouvelle dépendance : `reqwest =0.13.5` (déjà au verrou, tirée par l'updater), `default-features = false`, feature `rustls-no-provider` + `rustls` 0.23 `aws_lc_rs` (fournisseur déjà compilé pour la synchro, y compris iPhone) : aucun nouveau paquet au verrou, aucun OpenSSL ni native-tls (`cargo tree -i openssl-sys` vide pour Windows et iOS). `cargo audit` tourne en CI. Le test de purge qui interdisait `reqwest` (client des agendas retirés) est adapté : il exige maintenant la version exacte et l'absence d'OpenSSL. Couches : domaine pur (`barcode.ts`, `offProduct.ts`), façade `src/platform/off`, écran de scan à la demande.
3. **nutrition.** Conversion par vecteurs ; kcal depuis `energy-kcal_100g`, sinon kJ / 4,184 ; jamais de zéro inventé ; fiche perso du même code prioritaire sur le cache ; fiche périmée proposée avec sa cause si le réseau échoue ; UPC-E développé pour vérifier la clé (ambiguïté EAN-8 / UPC-E : lu comme EAN-8 quand les deux sont valides).
4. **security-privacy** (relecture sans modification) : verdict CONFORME, aucun bloquant. Un point moyen (aucun test de redirection) : tests ajoutés, port comparé en plus de l'hôte. Remarques gardées : proxy d'environnement conservé (défaut reqwest), erreurs de client regroupées selon le contrat, texte distant affiché en texte pur (jamais de HTML), bornes des valeurs côté domaine.
5. **qa-test.** Tests rouges dans des commits séparés avant chaque fonction (domaine, façade, écrans, Rust). Serveur HTTP local simulé côté Rust (aucun appel réel à OFF en CI) : trouvé, inconnu, JSON invalide, 429, 503, délai, hors ligne, taille, filtre des clés, garde de débit, journaux sans code ni texte, confidentialité de la requête (URL, code ou texte, User-Agent). Garde du bundle : `BarcodeScanView.tsx` et `platform/off/index.ts` hors du départ, liste blanche inchangée.
6. **code-reviewer.** Relecture à froid avant fusion (voir la PR).
