Itération : I0 | Taille : L | Budget tokens : 400 k maximum
Statut : préparé, non exécuté ; dépend de SPA-004 ; suit SPA-006 dans l'ordre I0.

## Objectif

Conclure H-4 avec un compteur fictif de 60 s dans la Dynamic Island et sur l'écran verrouillé, via une extension WidgetKit/ActivityKit injectée après génération Xcode. Éprouver le fallback minuteur dans l'app et notification locale.

## Critères d'acceptation (Given / When / Then)

1. **Étant donné** un projet fraîchement généré, **quand** le script post-init est exécuté une puis deux fois, **alors** une seule cible d'extension existe, avec sources durables, dépendance/embedding et identifiants cohérents ; régénérer Xcode ne la perd pas. Projet incompatible : échec explicite, pas de publication incomplète.
2. **Étant donné** le build sans signature, **quand** la CI signe l'extension puis l'app et reconstitue l'IPA, **alors** les deux signatures, leurs plist/entitlements et la présence de l'extension sont contrôlés sur l'IPA finale ; SHA-256 et source.json portent ces octets. Aucun App Group, push ou mode de fond ajouté.
3. **Étant donné** l'IPA re-signée par SideStore, **quand** Ali lance le compteur de 60 s, **alors** il apparaît dans la Dynamic Island et sur écran verrouillé ; SideStore identifie l'extension et sa consommation d'identifiant d'app est relevée. Fin/arrêt ferme l'activité sans activité orpheline.
4. **Étant donné** une date de fin persistée, **quand** l'app passe en arrière-plan, est verrouillée puis rouverte, **alors** le temps restant est recalculé depuis cette date, sans dérive d'un compteur JS suspendu. La notification locale arrive à l'échéance, sans doublon après reprise.
5. **Étant donné** une activité indisponible/refusée ou H-4 BLOCKED, **quand** le compteur est lancé, **alors** le timer in-app et la notification iPhone assurent le fallback, état expliqué ; sur PC, timer in-app sans notification système obligatoire. Refus des notifications visible, aucune promesse de notification livrée.
6. **Étant donné** les essais, **quand** H-4 est conclu, **alors** CONFIRMED exige les captures natives et la fin correcte ; BLOCKED exige motif étayé et ADR de fallback accepté. H-16 est recontrôlée si l'extension change le quota ; aucune app supprimée pour réussir.

## Tests à écrire

Commit rouge puis vert : injection idempotente, absence d'extension, cible/embedding, ordre signature/zip, contrats plugin et stub, date de fin persistée, reprise à horloge contrôlée, arrêt et absence de doublon, indisponibilité/refus. Réception native prouvée séparément sur iPhone.

Local : Vitest ciblé sans couverture, lint, typecheck, bundle avant push ≤ 358 400 octets gzip. Suite complète avec couverture domaine ≥ 80 %, e2e et smoke en CI. Une compilation iPhone pour le lot terminé ; aucun build pour documentation, aucun e2e local ni timeout allongé.

Injection Xcode fragile ou signature d'extension refusée : preuve exacte, pas de CONFIRMED par build seul. Si limitation native démontrée, BLOCKED et fallback minuteur/date persistée + notification prouvée ; sinon ticket ouvert. Aucune suppression/réinstallation comme remède au quota.
