Itération : I6 | Taille : M | Budget : 150 k tokens maximum
Statut : préparé, conditionnel à la décision Q-4 ; dépend des modèles I1 et de la sortie I5.

## Objectif

Si Ali confirme le besoin, importer un historique d’entraînement CSV Hevy et/ou Strong, avec aperçu, mapping d’exercices et validation avant insertion. Sans décision positive, clôturer comme `DEFERRED`, sans code d’import.

## Hors périmètre

Synchronisation directe avec les services Hevy/Strong, connexion de compte, upload, import de programme (I6-06), modification ou déduplication silencieuse de séances existantes.

## Références PRD : § 14, 17.1, 21.3, 22–23 | Question : Q-4

## Critères d’acceptation (Given / When / Then)

1. **Étant donné** Q-4 négatif, **quand** le ticket est clos, **alors** le statut est `DEFERRED`, aucune intégration externe n’est ajoutée et l’import Spartiate existant reste inchangé.
2. **Étant donné** Q-4 positif et un format explicitement choisi, **quand** le fichier est sélectionné, **alors** format, colonnes, date, unités et encodage sont validés avant toute écriture.
3. **Étant donné** un exercice reconnu ou inconnu, **quand** le mapping est affiché, **alors** l’utilisateur corrige ou ignore explicitement ; le fichier source n’est pas modifié.
4. **Étant donné** un aperçu confirmé, **quand** l’import est exécuté, **alors** seule l’histoire sélectionnée est créée, sans écraser une séance existante ; doublons potentiels sont signalés.
5. **Étant donné** un fichier invalide ou une interruption, **quand** l’import échoue, **alors** aucune écriture partielle n’est présentée comme réussie.

## Tests rouges avant implémentation

Après décision positive : fixtures CSV synthétiques pour chaque dialecte approuvé, colonnes manquantes, formats de dates/unités, exercices inconnus, doublons, import répété, annulation et transaction atomique. Aucune donnée réelle d’Ali.
