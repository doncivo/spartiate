# FIX-0182 — e2e `Y-IOS-02` : 404 intermittents du simulateur de dossier

Ticket ouvert le 13/11/2026 par l'agent principal : `Tests` sur main rouge après la fusion de DEP-01 (#113, run 43332958413), job « e2e iphone (4/4) », `tests/e2e/Y-IOS-02.spec.ts:79` « simulateur de dossier : /scan → 404 ». Même test, autre route, déjà rouge sur la PR #112 (run 43323473094, `/camera → 404`, ligne 29), sans rapport avec le diff de l'une ou l'autre PR. Règle FIX-0115 : aucun tag 0.18.1 tant que main n'est pas vert. Test seulement, code de l'app inchangé, pas de version.

## Cause

Le simulateur de dossier (`tests/sim/syncFolderSim.ts`) ne crée un appareil qu'au premier appel `/rpc` de sa page (`deviceOf`, création asynchrone mémorisée dans `room.creating`). `openSyncedPage` rend la main dès que la barre de navigation est visible ; la page peut ne pas avoir encore fait ce premier appel, ou être en pleine création. Les routes de pilotage (`/camera`, `/scan`, `/fail`, `/inspect`, `/testing`, `/unreachable`) cherchaient l'appareil dans `room.devices` seulement et répondaient 404 sur-le-champ : course entre le test et le démarrage de la synchro de la page, plus fréquente sous charge.

## Correction

`awaitDevice(rooms, room, nom, DEVICE_WAIT_MS)` : appareil déjà enregistré, rendu ; création en cours, attendue ; pas encore commencée, attendue jusqu'à 10 s (`DEVICE_WAIT_MS`, constante nommée) ; au-delà, `undefined` et la route répond 404 comme avant. Les six routes de pilotage l'utilisent. Aucun délai de test, aucun budget (`BUDGET_MS` de Y-IOS-02 : 40 s inchangé), aucune attente Playwright n'est allongée ; aucun test désactivé ni nouvel essai.
